PRESERVING VS CODE SETTINGS ACROSS SESSION REPROVISIONING
=========================================================

PROBLEM:
When you: ./scripts/launcher.sh remove 1
Then:    ./scripts/launcher.sh create 1 <new-path>

The VS Code configuration volumes are deleted, so you lose all settings.

SOLUTION 1: Remove Session WITHOUT Removing Volumes
────────────────────────────────────────────────────

# Stop and remove ONLY the container (keep volumes)
podman rm -f vscode-session-1

# Create new session with same session number (will reuse volumes)
./scripts/launcher.sh create 1 /new/workspace/path

# VS Code settings preserved! ✓
# Workspace changed! ✓


SOLUTION 2: Backup Volumes Before Removing
────────────────────────────────────────────

# Backup config volume
podman run --rm -v vscode-session-1-config:/data -v /tmp:/backup \
  alpine tar czf /backup/vscode-config-backup.tar.gz -C /data .

# Remove session (including volumes)
./scripts/launcher.sh remove 1

# Create new session
./scripts/launcher.sh create 1 /new/workspace/path

# Restore config
podman run --rm -v vscode-session-1-config:/data -v /tmp:/backup \
  alpine tar xzf /backup/vscode-config-backup.tar.gz -C /data

# VS Code settings restored! ✓


SOLUTION 3: Use Host Path Binding (Persistent Settings)
─────────────────────────────────────────────────────────

Edit docker-compose.yml and replace:
  - vscode-session-1-config:/home/vscode/.config/code-server

With:
  - ~/.vscode-container-session-1:/home/vscode/.config/code-server:rw

This binds to your home directory, so settings persist across container removal.


QUICK REFERENCE: Remove Session WITHOUT Losing Settings
─────────────────────────────────────────────────────────

# Just stop and remove the container
podman rm -f vscode-session-1

# OR use compose (keeps volumes)
podman-compose -f docker-compose.yml down --remove-orphans

# Create new session with same number
./scripts/launcher.sh create 1 /new/workspace/path

# Config volumes still exist and will be reused!
